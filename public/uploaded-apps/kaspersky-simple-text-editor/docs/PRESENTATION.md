## 📌 Слайд 2 · Проблема: Как было раньше

### Боль, которую знает каждый в команде

```
  Маркетолог           Дизайнер            Верстальщик          QA / Тест
  ┌─────────┐         ┌─────────┐         ┌─────────┐         ┌─────────┐

  │  + ТЗ   │         │  Figma  │         │  код    │         │ Outlook │
  └─────────┘         └─────────┘         └─────────┘         └─────────┘
        │                   │                   │                   │
        └───────────────────┴───────────────────┴───────────────────┘
                              4–5 рабочих дней
                              3–4 человека в процессе
                              Каждая правка = новый цикл
```

> **Описание графика:** Горизонтальная временная шкала (timeline) с четырьмя этапами — каждый обозначен иконкой роли (человечек с ноутбуком, палитра, знак кода `</>`, чек-лист). Стрелки между этапами подписаны количеством дней. Внизу — красная плашка с итоговым временем: «4–5 рабочих дней».

### Ключевые болевые точки

| # | Проблема | Влияние на бизнес |
|---|----------|-------------------|
| 1 | **Ручная HTML-вёрстка** — каждый дайджест верстается с нуля | ⏱ 3–4 часа чистого кодирования на один выпуск |
| 2 | **Outlook-несовместимость** — CSS ломается в Outlook 2016/2019/365 | 📉 До 30% получателей видят «битую» рассылку |
| 3 | **Зависимость от верстальщика** — маркетолог не может сам собрать письмо | 🔄 Каждая правка = запрос верстальщику + ожидание |
| 4 | **Нет единого шаблона** — каждый выпуск стилистически отличается | 🎨 Бренд размывается от выпуска к выпуску |
| 5 | **Нет версионирования** — сложно откатиться к прошлой версии | 💾 Потеря работы при ошибке |

## 📌 Слайд 3 · Решение: Newsletter Constructor Pro

### Один инструмент вместо цепочки из четырёх

```
                    ┌──────────────────────────────────────┐
                    │                                      │
  Маркетолог ──────▶│   Newsletter Constructor Pro         │──────▶ Готовый
                    │                                      │        email
                    │   Визуальный редактор + Экспорт      │        (.html)
                    │   Outlook-совместимый + Responsive    │
                    │                                      │
                    └──────────────────────────────────────┘
                              40 минут
                              1 человек
                              0 строк кода вручную
```

> **Описание визуала:** Минималистичная схема: слева — иконка маркетолога (один человек), стрелка ведёт к большому зелёному прямоугольнику с логотипом NCP, из которого выходит стрелка к иконке готового email-файла. Под схемой — три крупных числа в зелёных кругах: «40 мин», «1 чел.», «0 кода».

### Что это?

**Newsletter Constructor Pro** — это браузерный визуальный редактор HTML-рассылок, который:

- 🖥 **Работает без сервера** — откройте `index.html` в Chrome/Edge и начните работу
- 📦 **Не требует установки зависимостей** — ни Node.js, ни npm, ни Docker
- 🏢 **Устанавливается как Windows-приложение** — ярлык на рабочем столе, запись в «Установка и удаление программ»
- 🔒 **Полностью офлайн** — никакие данные не покидают машину пользователя

### 📧 Outlook-совместимость из коробки

```
  Исходный CSS                    После обработки NCP
  ─────────────                   ────────────────────
  display: flex;           →      <table role="presentation">
  border-radius: 8px;      →      (удалено, предупреждение)
  background-image: url(); →      bgcolor="#006D5B"
  font-size: 1.2rem;       →      font-size: 16px;
  animation: fade-in;      →      (удалено)
  box-shadow: 0 2px 4px;   →      (удалено)

  + MSO conditionals:
    <!--[if mso]>...<![endif]-->
    <!--[if gt mso 12]>...<![endif]-->
```

> **Описание графика:** Таблица «до и после» в двух колонках. Слева — красные строки с зачёркнутым CSS-кодом. Справа — зелёные строки с Outlook-безопасным HTML. Внизу — бейдж «Outlook Compatibility Score: 95/100» в зелёном круге.

**4-этапный pipeline экспорта для Outlook:**

| Шаг | Функция | Что делает |
|-----|---------|-----------|
| 1 | `inlineAllStyles()` | Все CSS-правила → inline `style` атрибуты |
| 2 | `convertStylesForOutlook()` | Удаление неподдерживаемого CSS, нормализация цветов в HEX |
| 3 | `flattenLayoutToTables()` | Flexbox / Grid → `<table role="presentation">` |
| 4 | `generateOutlookHtmlWithMso()` | Обёртка в MSO conditionals, Office Document Settings |

**Валидация в реальном времени:**
- ⚠️ Бейджи предупреждений на каждом блоке с несовместимым CSS
- 📊 Генерация отчёта совместимости (0–100 баллов) по кнопке «Validate Outlook»
- Проверяется: `border-radius`, `box-shadow`, `flexbox`, `grid`, `animation`, `filter`, отсутствие `alt`-текста, ширина > 600px

```
  │   Сервер: НЕ нужен (file:// протокол)            │
  └──────────────────────────────────────────────────┘
```

> **Описание визуала:** Архитектурная диаграмма с единственным блоком «Браузер» — внутри иерархия файлов (дерево), от index.html расходятся ветки к CSS и JS модулям. Каждый JS-модуль подписан одним словом-назначением. Снизу — три иконки с перечёркнутыми знаками: «No Server», «No Network», «No Dependencies».

### 🏆 Ключевые архитектурные преимущества

| Свойство | Деталь | Почему это важно |
|----------|--------|------------------|
| **Zero-dependency** | Единственная внешняя библиотека — JSZip (минифицирована) | Нет риска supply-chain атак, нет `node_modules` |
| **100% офлайн** | Никаких API-вызовов, CDN, Analytics | Данные клиентов не покидают корп. сеть |
| **Файл = приложение** | `index.html` + `app/` = весь софт | Копирование папки = деплой |
| **localStorage** | Автосохранение каждые 2 мин + 5 сек debounce + при закрытии вкладки | Работа не теряется даже при крахе браузера |
| **Undo × 50** | 50 состояний с восстановлением позиции курсора | Любое действие можно отменить |
| **Модульность** | 15 файлов с чёткими зонами ответственности | Легко поддерживать и развивать |
